# Repoformer scorer verification

Pinned creator snapshot: [run_cceval.sh](https://github.com/amazon-science/Repoformer/blob/5b0571318e9918fd2af132c4b35077f9ea331133/finetuning/evaluation/run_cceval.sh) calls [eval_vllm_repoformer.py](https://github.com/amazon-science/Repoformer/blob/5b0571318e9918fd2af132c4b35077f9ea331133/repo_eval/eval_vllm_repoformer.py) with `--compute_cceval_metric`, dispatching to [eval_metric_cceval.py](https://github.com/amazon-science/Repoformer/blob/5b0571318e9918fd2af132c4b35077f9ea331133/repo_eval/eval_metric_cceval.py). Its default final loop runs line completion in four languages, NOT CrossCodeLong chunk/function. Although the shell function has branches for chunk/function, those branches are not invoked by its checked-in final loop. We cannot establish from that alone which scorer produced the paper's CrossCodeLong table.

Flag-enabled CCEval scorer: [cceval_utils.py](https://github.com/amazon-science/Repoformer/blob/5b0571318e9918fd2af132c4b35077f9ea331133/repo_eval/cceval_utils.py) first postprocesses the Python prediction into one parseable statement using tree-sitter; it then regex-removes `#.*` and `//.*` from prediction and target. EM compares arrays of nonempty lines with leading/trailing whitespace stripped on each line. It does not remove internal whitespace or discard line boundaries. Thus local all-whitespace removal has different behavior from this scorer. Be careful: this is the invoked scorer for the script's default line task, not proven the paper's chunk scorer.

Without the flag, [eval_metric.py](https://github.com/amazon-science/Repoformer/blob/5b0571318e9918fd2af132c4b35077f9ea331133/repo_eval/eval_metric.py) handles chunk as API completion: it retains the first N nonempty predicted lines, where N is the number of nonempty reference lines; it computes EM by `tokenize_code`, which spaces non-alphanumeric/underscore characters, splits lowercase-to-uppercase boundaries, collapses whitespace, maps both quote types to backticks, splits into tokens, then compares token arrays. This is neither simple all-whitespace removal nor the flag-enabled per-line comparator. Its function completion path uses tree-sitter processing. The [paper Appendix A](https://arxiv.org/html/2403.10059v2#A1) specifies reference-line truncation for chunk and tree-sitter function extraction, consistent with the latter path, but paper alone does not prove exact code version/scorer selection for every table row.

Both implementations expose two edit metrics. `cal_edit_sim_repoeval` strips leading/trailing whitespace from the entire prediction and reference and calculates `1 - editdistance.eval(pred, gold) / max(len(pred), len(gold))`, then aggregates and reports percent; if both strings are empty it contributes zero. `cal_edit_sim` separately applies `fuzzywuzzy.fuzz.ratio` to whole-string stripped text and averages its 0–100 scores. Under the flag, prior statement extraction and comment removal affect both. The paper's normalized Levenshtein definition supports the former as its described ES; the exact association of table outputs with files and the pinned clean-data patch is not independently established.
